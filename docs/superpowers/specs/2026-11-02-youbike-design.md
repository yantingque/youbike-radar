## 1. 目的與成功標準

**目的**：做出一個 12 月求職用的代表作，完整展示「資料收集 → 清理 → 分析 → 建模 → 上線服務」。

**使用者**：通勤族。核心問題是「我常去的那一站，30 分鐘後還有沒有車／有沒有位子？」

**成功標準**

| 成果 | 驗收標準 |
|---|---|
| 自動收集管線 | GitHub Actions 每 10 分鐘收集，連續 ≥ 4 週，每日遺漏率 < 5%（有每日報表佐證） |
| EDA | ≥ 8 張有結論的圖表（全臺北） |
| 需求模型（第一段） | 測試月 MAE 優於「同站同星期同時段過去 4 週平均」 |
| 風險模型（第二段） | PR-AUC 同時優於「維持現狀」與「上週同時段」兩個 baseline，並報告轉變案例的表現 |
| 儀表板 | 公開網址，地圖顯示各站 30 分鐘後風險，資料延遲時有警示 |
| LINE 推播（加分） | 固定站點風險超過門檻時實際收到推播 |

**假設**：判斷作品好壞的是「面試官看得懂、相信它真的在跑」，而不是準確度做到最高。

## 2. 已定案的決策

| 決策 | 結論 | 理由 |
|---|---|---|
| 使用者 | 通勤族 | 問題最具體，面試最好講 |
| 預測目標 | 兩段式：歷史資料預測每站每小時借出／還入量 → 當特徵 → 快照預測 30 分鐘後空站／滿站 | 快照只有約 4 週；一條線卡住還有另一條能交成果 |
| 空站／滿站定義 | 可借 ≤ 2 台＝空站風險；可還 ≤ 2 位＝滿站風險 | 符合「走到站可能就沒了」的感受；事件較多、較好學 |
| 預測時間 | 30 分鐘後（60 分鐘列為範圍外） | 集中範圍 |
| 模型範圍 | 全臺北一個模型（開發時先用一區跑通） | 資料多 8 倍，對短期快照很重要 |
| 成果形式 | Streamlit 儀表板為主，LINE 定時推播為加分 | 儀表板最容易公開展示 |
| 收集方式 | GitHub Actions＋精簡欄位＋壓縮，存到 `data` 分支 | 不必開著電腦；沿用 stock-system 經驗 |
| 架構 | 排程批次預測：Actions 收集後緊接著預測，儀表板只讀結果 | 一條管線最穩，儀表板輕快 |
| 歷史資料 | 最近 12 個月（2025/08 ~ 2026/07） | 涵蓋四季與寒暑假 |
| 新北市 | 預測不涵蓋；OD 分析把新北站歸成「新北」一類 | 範圍控制 |
| 天氣 | 歷史：CODiS 臺北測站 466920 逐時；即時：氣象署開放資料 API | 唯一官方來源 |

## 3. 系統元件與資料流

```
          ┌───────── GitHub Actions（每 10 分鐘）─────────┐
YouBike   │ ① 收集器 → ② 預測器                          │
即時 API ─→│   精簡快照     讀最近 1 小時快照＋模型＋天氣   │
          └──────┬──────────────┬────────────────────────┘
                 ▼              ▼
          data 分支：      data 分支：
          snapshots/       predictions/latest.parquet ─→ ⑥ Streamlit 儀表板
                 │                                      └→ ⑦ LINE 推播（加分）
                 ▼  （每日整併）
          snapshots/YYYY-MM-DD.parquet ─┐
                                        ├→ ⑤ 風險模型訓練（本機，每週重訓）
歷史 zip → ③ 歷史管線(DuckDB) → ④ 需求模型 ┘
```

| # | 元件 | 輸入 → 輸出 | 執行位置 |
|---|---|---|---|
| ① | 收集器 | 即時 API → 每輪一個壓縮小檔，欄位 `collect_time, sno, available_rent_bikes, available_return_bikes, act, mday`；站點主檔（`sno, sna, sarea, latitude, longitude, Quantity`）每天更新一次 | Actions，每 10 分鐘 |
| ① b | 每日整併 | 前一天的小檔 → `snapshots/YYYY-MM-DD.parquet`＋當日遺漏率寫入品質報表 | Actions，每天一次 |
| ② | 預測器 | 最近 1 小時快照＋即時天氣＋模型檔 → `predictions/latest.parquet`（每站 `p_empty`, `p_full`, `data_age_min`, `predicted_at`） | Actions，緊接在 ① 之後 |
| ③ | 歷史管線 | 12 個月 zip → 清理、站名對照（含人工對照表、排除內部站點）→「站 × 小時」借出／還入量表 | 本機，一次性 |
| ④ | 需求模型 | ③＋天氣＋假日＋站點屬性 → 每站每小時預期借出／還入量 | 本機 |
| ⑤ | 風險模型 | 快照＋④＋天氣＋站點屬性 → 空站、滿站兩個分類器，模型檔存在 main 分支 | 本機，每週重訓 |
| ⑥ | 儀表板 | `latest.parquet`＋站點主檔 → 地圖、高風險排行、行政區篩選 | Streamlit Community Cloud |
| ⑦ | LINE 推播 | `latest.parquet` → 固定站點超過門檻時推播 | Actions（加分） |

**分支**：main 放程式碼與模型；`data` 分支只放快照、品質報表、預測結果。

**資料量估算**：精簡＋壓縮後約 2~3 MB／天，6 週約 100 MB。

**要新增的資料**：臺北捷運站出口座標（臺北市資料大平臺），用來算「離最近捷運站的距離」。

## 4. 模型設計

### 4-1 第一段：需求模型

- **單位**：站 × 小時；分別預測借出量、還入量
- **特徵**：小時、星期、假日／補班、月份、逐時雨量與氣溫、站點容量、行政區、離最近捷運站距離、上週同時段的量
- **模型**：LightGBM，Poisson 目標
- **切分**：2025/08 ~ 2026/05 訓練、2026/06 驗證、2026/07 測試（照時間，不隨機）
- **Baseline**：同站、同星期、同時段過去 4 週平均
- **指標**：MAE，另外報告尖峰時段（07–09、17–19）
- **輸出給第二段**：這一小時與下一小時的預期淨流量（預期還入 − 預期借出）

### 4-2 第二段：風險模型

- **單位**：(站, 快照時間 *t*)
- **標籤**：取 *t*+30 分鐘前後 5 分鐘內最接近的快照；`y_empty = 可借 ≤ 2`、`y_full = 可還 ≤ 2`；找不到快照就丟掉該樣本
- **特徵**：
  - 目前可借、可還、有效容量（可借＋可還）
  - 過去 10／30／60 分鐘的變化量
  - 時段、星期、是否假日
  - 雨量、氣溫
  - 第一段預期淨流量
  - 站點屬性（容量、行政區、捷運距離）
  - 該站該時段在訓練期間「≤ 2」的出現頻率（只用訓練期資料計算）
- **排除**：`act = 0` 的站；`mday` 超過 30 分鐘沒更新的快照
- **切分**：照時間，前 3 週訓練、最後 1 週測試，加上往前滾動驗證
- **Baseline**：
  1. 維持現狀：以目前可借（或可還）數量當分數
  2. 上週同時段：收滿一週後才計算
- **指標**：PR-AUC、精準度 = 0.5 時的 Recall（「推播兩次至少一次是對的」）；另外單獨報告轉變案例（目前 > 2、30 分鐘後 ≤ 2）
- **門檻**：在驗證集選定，用於儀表板顏色與 LINE 推播

## 5. 錯誤處理

| 元件 | 狀況 | 處理方式 |
|---|---|---|
| 收集器 | API 逾時、回傳站數 < 1,500 | 重試 2 次；仍失敗就不寫入，該次 Actions 標成失敗（GitHub 寄信通知） |
| 預測器 | 最近 1 小時快照不足 | 變化量特徵改用 60 分鐘內最接近目標時間的較早快照計算；60 分鐘內完全沒有就設為 0 並標記 `features_degraded = true`；`data_age_min` 記錄資料延遲 |
| 預測器 | 天氣 API 失敗 | 用最近一筆觀測值 |
| 儀表板 | `predicted_at` 超過 30 分鐘前 | 頁面上方顯示「資料延遲」警示 |
| 每日整併 | — | 計算遺漏率（實收次數 ÷ 144），寫入品質報表 |

## 6. 測試

以 TDD 保護下列純函式：

1. 站名清理與對照：去掉 `YouBike2.0_` 前綴、亂碼對照表、排除內部站點
2. 快照對齊到 10 分鐘格點；*t*+30 分鐘標籤產生，包括前後 5 分鐘找不到快照的情況
3. 不洩漏未來資料：*t* 的特徵只用到 *t* 以前的快照
4. 時間切分的訓練、驗證、測試區間互不重疊
5. 端對端冒煙測試：一小份固定資料從收集格式跑到 `latest.parquet`
